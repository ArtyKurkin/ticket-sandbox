## 12. `service-bind-localhost` — сервис работает локально, но недоступен по сети

**Поломка:** приложение запущено и исправно отвечает на порту `8080`, если обращаться к нему через `127.0.0.1`. Но процесс слушает только loopback-интерфейс, поэтому подключиться к сервису через сетевой адрес сервера нельзя.

Исходная настройка приложения находится в:

```text
/opt/customer-app/app.conf
```

Сервис управляется командами:

```bash
systemctl status customer-app
systemctl restart customer-app
```

Задание специально построено так, чтобы `systemctl status` показывал рабочий процесс, а локальный `curl` успешно отвечал. Нужно определить, **на каком адресе** слушает TCP-сокет.

### Диагностика

```bash
# приложение действительно запущено
systemctl status customer-app

# локально сервис работает
curl http://127.0.0.1:8080/
# APP OK: customer service is running

# посмотреть не только порт, но и адрес LISTEN
ss -lntp | grep ':8080'
```

В исходном состоянии будет видно примерно:

```text
LISTEN ... 127.0.0.1:8080 ...
```

Это означает, что приложение принимает соединения только через loopback.

Посмотреть сетевые адреса сервера:

```bash
ip -4 addr
```

или:

```bash
hostname -I
```

Можно сравнить доступность через loopback и через адрес сетевого интерфейса:

```bash
curl http://127.0.0.1:8080/

IP=$(ip -4 -o addr show scope global | awk '{split($4,a,"/"); print a[1]; exit}')
curl "http://$IP:8080/"
```

Первый запрос работает, второй — нет.

Посмотреть конфигурацию приложения:

```bash
cat /opt/customer-app/app.conf
```

### Решение

Открыть конфигурацию:

```bash
nano /opt/customer-app/app.conf
```

В исходном состоянии:

```env
BIND_ADDRESS=127.0.0.1
PORT=8080
```

Чтобы сервис принимал подключения через сетевые интерфейсы, изменить bind address:

```env
BIND_ADDRESS=0.0.0.0
PORT=8080
```

После изменения приложение нужно перезапустить:

```bash
systemctl restart customer-app
```

Проверить listener:

```bash
ss -lntp | grep ':8080'
```

Теперь ожидается:

```text
0.0.0.0:8080
```

Проверить локально:

```bash
curl http://127.0.0.1:8080/
```

И через сетевой интерфейс:

```bash
IP=$(ip -4 -o addr show scope global | awk '{split($4,a,"/"); print a[1]; exit}')
curl "http://$IP:8080/"
```

Оба запроса должны вернуть:

```text
APP OK: customer service is running
```

**Проверка пройдёт когда:** приложение запущено, продолжает отвечать локально на `8080` и доступно по этому же порту через сетевой интерфейс контейнера.

> Ключевой урок: открытый порт — это не только номер порта. Важно, **на каком IP-адресе процесс сделал bind**.
>
> `127.0.0.1:8080` и `0.0.0.0:8080` — принципиально разные состояния. В первом случае сервис доступен только с самого сервера, во втором — принимает соединения на всех IPv4-интерфейсах.
>
> Поэтому при кейсе «локально работает, снаружи нет» одной проверки `systemctl status` недостаточно. Нужно смотреть listener через `ss -lntp`.
