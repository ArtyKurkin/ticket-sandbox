# Roadmap Actions & Navigation

Карточки Roadmap теперь получают реальные серверные действия. Sandbox можно открыть после завершения технической программы и вернуться к доработкам. Наставник получает существующую страницу адаптации и итог ИС. Обычный стажёр не получает ссылки на staff-only дневник.

## Найденные маршруты и права

| Django name | URL | Доступ / использование |
|---|---|---|
| sandbox:dashboard | /sandbox/ | login_required; стажёр видит собственные задачи своей очереди/уровня, staff — панель наставника. Используется для «Перейти к заданиям». |
| sandbox:task_detail | /attempts/<attempt_id>/ | Владелец своей попытки либо staff. Не подставляется как переход Roadmap: Roadmap не готовит попытки. |
| traineediary:trainee_detail | /diary/trainees/<journey_id>/ | login_required + is_staff. Существующая карточка включает прогресс, историю, метрики и сохранённый итог ИС. Используется для staff-действий. |
| traineediary:dashboard | /diary/ | is_staff; обзор адаптаций, не персональная страница стажёра. |
| traineediary:weekly_metrics | /diary/metrics/ | is_staff; не предлагается обычному стажёру. |
| traineediary:trainees_kanban | /diary/trainees/ | is_staff; существующее управление адаптациями. |
| traineediary:complete_trainee | /diary/trainees/<journey_id>/complete/ | is_staff, существующая форма завершения с CSRF. Действие Roadmap на этот маршрут не создаётся. |

Все внутренние действия сформированы через reverse(). Персональной страницы TraineeDiary и отдельной страницы результатов с доступом обычного стажёра не найдено. Самостоятельно расширять права или создавать такой интерфейс эта задача не стала. Фактические данные по-прежнему доступны владельцу в Roadmap API и карточках.

В исходном коде/settings не было настройки URL Teachbase; добавлена явная конфигурация без вымышленного адреса и без изменений реальных .env файлов.

## Контракт actions

```json
{
  "code": "open_sandbox",
  "label": "Перейти к заданиям",
  "url": "/sandbox/",
  "enabled": true,
  "kind": "learning",
  "external": false
}
```

code — стабильный код; label — текст кнопки; url — серверный URL либо null, если переход не настроен; enabled — доступность конкретного действия; reason — объяснение недоступности, обязательно для disabled действия. kind отделяет learning (переход к обучению) от view (разрешённое чтение адаптации/результата). external указывает внешний переход.

Пример незаданного Teachbase:

```json
{
  "code": "open_training",
  "label": "Перейти к обучению",
  "url": null,
  "enabled": false,
  "kind": "learning",
  "external": true,
  "reason": "Ссылка на программу Teachbase не настроена. Обратитесь к наставнику."
}
```

Неразрешённое действие не превращается в кнопку: карточка показывает reason. При отсутствии подходящей персональной страницы actions=[], а optional action_notice содержит объяснение. coming_soon и not_required всегда остаются без действий; неприменимые учебные действия не предлагаются даже наставнику. Без адаптации действий нет.

Доступность, статус, знаменатель прогресса, техническое доказательство и readiness не изменялись. Привязка действий к viewer выполняется после read-only агрегации; API явно передаёт request.user. Непроверенный viewer, анонимный пользователь и посторонний обычный пользователь не получают ссылок на чужую адаптацию.

## Кнопки по роли

| Станция | Стажёр | Staff |
|---|---|---|
| 01 training | «Перейти к обучению», если этап применим и настроен допустимый URL; иначе причина без кнопки. | То же для применимой адаптации. |
| 02 sandbox | «Перейти к заданиям» для available/in_progress/completed. После технического успеха и при доработках переход остаётся. | Тот же существующий маршрут; Sandbox самостоятельно отображает панель наставника. |
| 03/04 | Нет рабочих действий, COMING SOON. | Аналогично. |
| 05–07 | Нет staff-only ссылки; объяснение отсутствия персональной страницы. Реальные метрики остаются в карточке. | «Открыть адаптацию» → существующая карточка конкретной адаптации. |
| 08 | Фактический результат в карточке, объяснение отсутствия отдельной персональной страницы. | При активной адаптации «Открыть адаптацию»; при сохранённом/неполном итоговом результате «Посмотреть результат ИС» → та же существующая карточка. |

Learning-действие заблокированного этапа disabled. Read-only view наставника может быть разрешён и для locked станции: это доступ к данным и проверке результата, а не запуск или завершение обучения. Поэтому прекращённый ИС с locked финалом всё ещё можно открыть в staff-карточке. Целевой маршрут повторно проверяет is_staff; скрытие кнопки не используется как авторизация.

Кнопки из API остаются недоступными в staff-демо. В React нет новых таблиц URL по этапам и нет конструирования ссылок из ID/названий.

## Конфигурация Teachbase и защита URL

Две переменные окружения/Django settings:

- ROADMAP_TEACHBASE_URL — фактический URL программы, по умолчанию пусто.
- ROADMAP_TEACHBASE_ALLOWED_HOSTS — точные разрешённые hostname через запятую, без схемы и порта; по умолчанию пусто.

Администратор должен взять реальный адрес из своей Teachbase-программы и отдельно указать его hostname. Реальная ссылка в рамках задачи не назначалась. После изменения настроек перезапустить Django.

Сервер проверяет URLValidator с HTTPS, точное совпадение хоста со списком, отсутствие userinfo, обратных слешей, пробелов/управляющих символов и нестандартных портов. Суффиксные домены, javascript/data/http, protocol-relative адреса, credentials и ошибочная конфигурация не возвращаются как ссылки. Разрешён только HTTPS с default/443 портом.

React получает actionExternalHosts из Django bootstrap, причём в список попадает только хост уже проверенного настроенного адреса. Список не берётся из URL-параметров или самого action.url. Клиент дополнительно проверяет внутренние локальные пути либо HTTPS и точный хост из bootstrap. Внешние ссылки имеют rel="noopener noreferrer" и открываются обычной навигацией в той же вкладке.

Ни URL, ни code, ни enabled, ни роль не принимаются как пользовательская настройка API: GET-параметры url/next не меняют действия, POST подтверждения по-прежнему разрешает только comment. Новый redirect/proxy endpoint не создавался, внутренние действия не содержат пользовательского next. Операционные исправления конфигурации выполняет администратор, не HTTP-клиент.

Production не читалась и не мигрировалась; реальные .env не редактировались. Ветка сохранена, commit/push/merge/deploy не выполнялись.

## Оставшиеся ограничения

Настоящий URL Teachbase и его разрешённый хост должен задать администратор. Для обычного стажёра отдельного персонального TraineeDiary/результата пока нет; использовать staff-only страницы нельзя, поэтому данные остаются в карточках Roadmap. Новый выбор чужого стажёра и UI завершения ИС не создавались. Конфигурация обучения глобальная, без назначения отдельных курсов пользователям. Награды и новые учебные приложения не реализовывались. Работа завершена для проверки.
