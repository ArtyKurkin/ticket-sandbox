# Data Center Journey — React Island

Дизайн берётся только из `design-references/roadmap/code.html`, `screen.png`
и `DESIGN.md`. В задаче интерфейс назван 1.1; исходник содержит подпись
`Roadmap 4.2`, она сохранена. Шрифты Inter, Geist и JetBrains Mono совпадают
с объявленными в Roadmap и переиспользуются из существующих локальных assets.
Фон дата-центра скачан по URL именно из экспорта Roadmap.

## Запуск

Из корня с настроенными Python-окружением, локальной БД и `DEBUG=True`:

```sh
npm ci --prefix frontend
npm run build --prefix frontend
python manage.py runserver
```

После обычного входа: http://127.0.0.1:8000/roadmap/.
Watch-сборка: `npm run dev --prefix frontend`, затем обновить страницу.

```sh
npm test --prefix frontend
npm run typecheck --prefix frontend
python manage.py check
python manage.py test react_frontend
```

Сборка обязательна до Django-тестов. Production: сборка frontend, затем
`python manage.py collectstatic --noinput` — тот же процесс, что у остальных islands.
CI дополнительно запускает `npm test`; новых зависимостей нет.

## Структура

- `RoadmapPage` — неизменяемое начальное состояние из Django и отдельный локальный демо-прогресс.
- `RoadmapShell` — панели исходного Roadmap и лёгкий параллакс фона.
- `RoadmapCanvas` — общая система координат станций и SVG, выбор этапа, прокрутка.
- `RoadmapStation`, `art/*` — кнопки станций и исходная псевдо-3D графика.
- `RoadmapPath` — точные cubic control points Stitch, будущий маршрут, заполнение и импульс.
- `StageDetails`, `positioning.ts` — измерение карточки, колец и подписей через refs/ResizeObserver;
  выбор среди боковых позиций и кандидатов вдоль границ препятствий.
- `LivingDataCenter` — группы LED и локальное освещение, зависящие от прогресса.
- `RoadmapDemoControls` — 1/8, 3/8, 6/8, 8/8, только при серверном canDemo.
- `types.ts`, `data.ts` — типы и временный набор восьми этапов из Stitch.

Станции и SVG используют координаты 1200×700 и один слой с одинаковым смещением.
Размеры их иконок остаются читаемыми. При недостатке места карта прокручивается
внутри рабочей области, без горизонтального переполнения всей страницы.

Алгоритм проверяет пересечения с кольцами станций и подписями, включая выбранный
этап. Если свободного места нет, временно резервируется дополнительное пространство
для карточки внизу прокручиваемой карты. Позиции станций, геометрия и масштаб пути
при этом не меняются. Карточка прокручивается в видимую область; запас убирается
после закрытия. Измерения повторяются при смене этапа, прогресса, размеров или шрифтов.

## Авторизация и ограничения

Django login_required защищает `/roadmap/`. canDemo приходит только из
`request.user.is_staff`; URL-параметры не влияют на него. Исходный прогресс
1/8, 12,5% и два трофея — временный fixture, не данные обучения пользователя.
Демо изменяет только React state и сбрасывается при перезагрузке. Запросов
на сохранение нет. Счётчик трофеев следует демонстрационной механике Stitch,
не связан с демоданными Trophy Room.

Заблокированные этапы доступны для просмотра, но действие отключено. Единственный
рабочий переход этапа — существующий Ticket Sandbox. Остальные материалы и новые
учебные процессы не подключены; их действия пока недоступны. В демо запуск отключён.
Trophy Room изменён только для добавления навигационной ссылки на Roadmap.

## Отличия и проверки

Сохранены исходные SVG и геометрия, композиция, фон, цвета и эффекты. Отличия:
серверный профиль вместо вымышленного имени; staff-only демо; корректные состояния
всех станций при изменении прогресса; отсутствие пересечений карточек со станциями;
внутренняя прокрутка на тесных экранах; процент записан с русской десятичной запятой.
Возможны небольшие различия типографики, теней и расположения инспектора.
Pixel-perfect соответствие не утверждается.

Браузер: Chromium, 1600×1280 для сравнения со screen.png, 1440×900,
1920×1080 и 390×844. Проверены все восемь карточек, границы, роли, демо-прогресс,
геометрия, клавиатура, Escape, закрытие снаружи, reduced motion и навигация.
Frontend unit-тесты покрывают расчёт позиций, недостаток места и порядок состояний.
Django-тесты проверяют сессии, role flag, URL и production manifest/collectstatic.

Далее — только по отдельной задаче: реальный прогресс, учебные маршруты и Django API.
